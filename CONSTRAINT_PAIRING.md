# Constraint pairing rules

*Which reasoning-format constraints can be imposed together, which combinations are forbidden, and how a
constraint changes when it is paired. Nothing here is about training; for the data pipeline see
`CONSTRAINT_MIX.md`.*

## The constraint set

Six constraints, all imposed on the model's reasoning (the think block), one instruction sentence each:

| constraint | what it requires | argument |
|---|---|---|
| `reasoning_language` | the whole reasoning is in language L | L ∈ {English, Spanish, French, Russian, Polish} |
| `number_words` | fewer than N words | N |
| `capital` | every letter uppercase, in whichever language the reasoning is in | — |
| `end_checker` | the reasoning ends with an exact phrase | one of six phrases |
| `no_comma` | no comma anywhere | — |
| `end_of_sentence` | every sentence ends with a target word | the word |

Relation to ReasonIF's six: `reasoning_language`, `number_words`, `end_checker`, `no_comma` are kept;
`english_capital` becomes `capital` (the "must be English" part is dropped); `json_format` is removed and
`end_of_sentence` (from CoTControl) takes its place. Chinese, Hindi and Arabic are not used as languages here.

## Forbidden combinations

| combination | why it cannot be satisfied |
|---|---|
| `end_checker` + `end_of_sentence` | the last sentence would have to end with the phrase *and* with the target word |

That is the only forbidden pair. Any set of two or three constraints that does not contain both end
constraints is allowed: **14 of the 15 pairs, 16 of the 20 triples.**

Two further conflicts are avoided by construction rather than by a rule:

- `json_format` is not in the set. It would conflict with `no_comma` (JSON needs commas between elements)
  and with both end constraints (a JSON document cannot end with a bare word or phrase).
- Chinese, Hindi and Arabic are not in the language list. They have no letter case (`capital` is undefined),
  Chinese has no word boundaries (`number_words` is undefined), and all three use their own comma characters
  (`no_comma` would never trigger).

## Adjustments when constraints are paired

A constraint's *argument* changes when it is paired; its rule does not.

### Language changes the words

When `reasoning_language` is present, anything the model is asked to write verbatim is given in that
language:

| language | `end_of_sentence` target word | `end_checker` phrases (one is chosen) |
|---|---|---|
| English | safe | THIS THOUGHT PROCESS WAS GENERATED BY AI · THIS REASONING WAS PRODUCED BY AI · THIS ANALYSIS WAS CREATED BY AI · THIS LOGIC WAS GENERATED THROUGH AI · THIS EXPLANATION IS AI-GENERATED · THIS ARGUMENT WAS CONSTRUCTED BY AI |
| Spanish | seguro | ESTE PROCESO DE PENSAMIENTO FUE GENERADO POR IA · ESTE RAZONAMIENTO FUE PRODUCIDO POR IA · ESTE ANÁLISIS FUE CREADO POR IA · ESTA LÓGICA FUE GENERADA MEDIANTE IA · ESTA EXPLICACIÓN ES GENERADA POR IA · ESTE ARGUMENTO FUE CONSTRUIDO POR IA |
| French | sûr | CE PROCESSUS DE PENSÉE A ÉTÉ GÉNÉRÉ PAR UNE IA · CE RAISONNEMENT A ÉTÉ PRODUIT PAR UNE IA · CETTE ANALYSE A ÉTÉ CRÉÉE PAR UNE IA · CETTE LOGIQUE A ÉTÉ GÉNÉRÉE PAR UNE IA · CETTE EXPLICATION EST GÉNÉRÉE PAR UNE IA · CET ARGUMENT A ÉTÉ CONSTRUIT PAR UNE IA |
| Russian | безопасно | ЭТОТ ХОД МЫСЛЕЙ БЫЛ СГЕНЕРИРОВАН ИИ · ЭТО РАССУЖДЕНИЕ БЫЛО СОЗДАНО ИИ · ЭТОТ АНАЛИЗ БЫЛ СОЗДАН ИИ · ЭТА ЛОГИКА БЫЛА СГЕНЕРИРОВАНА С ПОМОЩЬЮ ИИ · ЭТО ОБЪЯСНЕНИЕ СГЕНЕРИРОВАНО ИИ · ЭТОТ АРГУМЕНТ БЫЛ ПОСТРОЕН ИИ |
| Polish | bezpiecznie | TEN PROCES MYŚLOWY ZOSTAŁ WYGENEROWANY PRZEZ AI · TO ROZUMOWANIE ZOSTAŁO WYGENEROWANE PRZEZ AI · TA ANALIZA ZOSTAŁA STWORZONA PRZEZ AI · TA LOGIKA ZOSTAŁA WYGENEROWANA PRZEZ AI · TO WYJAŚNIENIE ZOSTAŁO WYGENEROWANE PRZEZ AI · TEN ARGUMENT ZOSTAŁ SKONSTRUOWANY PRZEZ AI |

Without `reasoning_language` the English word and phrases are used. `number_words` and `no_comma` are
language-independent; the word count and the comma check simply apply to the text in that language.

### Capital changes the case

When `capital` is present, the `end_of_sentence` target word is written in upper case in the instruction
(SAFE, SEGURO, SÛR, БЕЗОПАСНО, BEZPIECZNIE), so the model is asked for exactly what the uppercase rule
allows. The `end_checker` phrases are upper case in every language already, so they need no change.
Both end-constraint checks are case-insensitive, so this adjustment is about consistency of the instruction,
not about passing.

### Word budget accounts for added words

When `number_words` is paired with a constraint that adds words, the budget N is set so the added words
fit: one word per sentence for `end_of_sentence`, the phrase length for `end_checker`. The rule itself
("fewer than N words") is unchanged; only N is chosen with that headroom.

### Everything else combines unchanged

`capital`, `no_comma`, `number_words` and `reasoning_language` combine with each other without any
adjustment: uppercase Cyrillic and Polish diacritics exist (ь → Ь, ł → Ł), language detection is unaffected
by upper-casing, and Spanish, French, Russian and Polish all use the ASCII comma.

## The valid combinations

**Pairs (14).** Every pair from the six except `end_checker` + `end_of_sentence`.

**Triples (16).** Every triple from the six except the four that contain both `end_checker` and
`end_of_sentence`: {end_checker, end_of_sentence, reasoning_language}, {…, number_words}, {…, capital},
{…, no_comma}.

## Held out for evaluation

These valid combinations are never used in training and are evaluated as unseen:

- Pairs: `capital` + `number_words` · `end_checker` + `reasoning_language` · `end_checker` + `number_words` ·
  `capital` + `no_comma`
- Triples: `end_checker` + `number_words` + `reasoning_language` · `capital` + `end_of_sentence` + `no_comma` ·
  `end_of_sentence` + `no_comma` + `number_words` · `end_of_sentence` + `no_comma` + `reasoning_language`

## Evaluation-side pairing (CoTControl, where `json_format` now lives)

The same logic applied to CoTControl's modes plus `json_format`:

| forbidden | reason |
|---|---|
| any two of uppercase / lowercase / alternating case | mutually exclusive |
| repeat sentences + end of sentence | the required repeated sentence ends with ">" |
| repeat sentences + meow between words | the required sentence must appear verbatim |
| json_format + meow / end of sentence / repeat sentences | a JSON document cannot carry "meow" between tokens or end with a word or phrase |
| json_format + uppercase / alternating case | JSON literals are case-sensitive |

`json_format` pairs with lowercase, word suppression, multiple word suppression and ignore question. All
other CoTControl combinations are allowed; word-suppression prompts whose forbidden keyword is the target word
are skipped.
